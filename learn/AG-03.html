Built-in Capabilities

Before building custom tools, know the powers models bring in the box: code execution, live web access, computer use, file systems — each a superpower with a sharp edge.

▶ Watch this reel

What you'll learn

  1. Code execution
  2. Web search & fetch
  3. Computer & browser use
  4. File system access

Remember this

  • Sandboxed code execution gives agents precision — no network, allow-listed reads, resource limits, ephemeral disk
  • Search + fetch close the freshness gap; synthesize with as-of dates and source triage
  • Computer/browser use is the no-API last resort — slow, brittle, and guarded by dedicated accounts + human confirmation; file tools live behind path-scoping

Code execution sandbox

  • Model writes code → sandbox runs → stdout/artifacts as observations.
  • Sandbox: no network, allow-listed reads, CPU/mem/time limits, ephemeral disk.
  • Working dir per session; truncate outputs; artifacts stored + linkable.

Web search & fetch

  • search: landscape; fetch: clean-text page → observation.
  • Discipline: source triage, as-of dates, truncation (summary-first), ToS.

Computer / browser use

  • For systems with NO API. Screenshots→actions (computer) or DOM (browser).
  • Slow, brittle; dedicated accounts, least privilege, human-confirm irreversibles.

File system tools

  • Workspace pattern: resolve()+prefix check, ext allow-list, read caps.
  • Composes with sandbox → full agent workshop (write/run/read/iterate).
